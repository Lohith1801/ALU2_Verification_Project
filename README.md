# ALU2_Verification_Project
Parameterized ALU Design and VerificationProject OverviewThis repository contains a high-performance, synthesizable Parameterized Arithmetic Logic Unit (ALU) implemented in Verilog. The design is engineered for flexibility, allowing for configurable data widths and command sets. It supports a comprehensive range of arithmetic and bitwise logical operations, including signed arithmetic with overflow detection and multi-cycle execution for complex operations.The project features a robust verification environment designed to ensure 100% functional reliability and high code coverage through directed and random testing.Key FeaturesConfigurable Architecture: Adjust data width and command width via top-level parameters.Multi-Latency Logic: Integrated counter logic to handle operations requiring two clock cycles for completion.Arithmetic Suite:Addition and Subtraction (Signed and Unsigned).Comparison flags: Greater (G), Lesser (L), and Equal (E).Signed overflow and carry-out detection.Logical Suite:Standard bitwise operations: AND, OR, XOR, NAND, NOR, XNOR.Logical and arithmetic shifts.Rotation logic (Rotate Left/Right).Validation Logic: Real-time error detection for input operand validity.Architecture and PinoutThe ALU serves as a synchronous module governed by a global clock and reset. It utilizes a two-stage internal pipeline for specific arithmetic commands.Signal DefinitionsNameDirectionDescriptionCLKInputSystem ClockRSTInputSynchronous ResetMODEInput1 for Arithmetic operations; 0 for Logical operationsINP_VALIDInputStatus bits for OPA (bit 0) and OPB (bit 1)CMDInput4-bit Operation selectorOPA, OPBInputPrimary data operandsRESOutputComputational result (extended width for multiplication)ERROutputAsserted if input validity does not match command requirementsVerification EnvironmentThe design is verified using a modular testbench architecture that separates stimulus generation from result checking.ComponentsDriver: Executes specialized tasks including walking-bit patterns, corner-case arithmetic, and toggle-specific stimulus.Reference Model: A behavioral model that executes in parallel with the DUT to provide golden results for comparison.Monitor and Scoreboard: Captures all interface transactions, performs bit-for-bit comparisons between the DUT and reference model, and logs pass/fail status to the simulation transcript.Performance MetricsThe design was validated using Questa SIM. Coverage analysis was performed to ensure design maturity:Statement and Branch Coverage: Verified that all operational paths and error states are exercised.Toggle Coverage: Confirmed that all internal registers and ports transition between all possible logic states.Functional Verification: All operations passed comparison against the reference model as per the project test plan.Setup and ExecutionCompilation:Compile the RTL and testbench files using a standard Verilog compiler.vlog ALU2_Design.v Driver.v ref_mod.v mon_scr.v TOP_tb.vSimulation:Run the simulation with coverage enabled.vsim -coverage work.test -c -do "run -all; exit"Reporting:Generate the HTML coverage report to view detailed metrics.vcover report -html coverage_results
